## M2 (Data pipeline and split)
- D3: The PlantVillage "color" images are mirrored at https://data.mendeley.com/datasets/tywbtsjrjv/1 (login required to download the official archive) and the Kaggle mirror at https://www.kaggle.com/datasets/abdallahalidev/plantvillage-dataset (also login). Neither is reliably downloadable from a headless sandbox without credentials. Per F1's "if it cannot be verified, accept a local folder and document the exact manual download step", the data CLI is built around a **local-folder source** (the production path) and a **URL source** (best-effort). The verify command, leakage test, and all tests run against a synthetic dataset shipped with the repo (`tests/_synth_data/` generated on demand). Real PlantVillage ingestion is documented in `data/DATASET_INFO.md` and the README — the user runs it once with their downloaded folder.
- D4: 8-orientation perceptual hash. We use `imagehash.phash` (DCT-based, robust to small edits) and compute it on all 8 D4 group elements (identity, 90/180/270 rotations, and the 4 mirrors). Two images are "same group" if the minimum Hamming distance between any pair of their 8 hashes is ≤ `group_hamming_threshold` (default 8, configurable in `configs/data.yaml`). This is a deliberately conservative threshold that catches both exact duplicates and the kind of near-duplicate augmentations PlantVillage contains.
- D5: Stratified group split. We use a per-class greedy group assignment so the per-class 70/15/15 ratio holds within 1% where class size allows. A class with fewer than ~3 groups gets placed in train; this exception is logged in `data_report.json` per F2.AC2's "where class size allows" clause.
